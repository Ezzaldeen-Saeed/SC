# مراقب المكالمات اللحظي — Real-Time Call Analyzer

نظام يراقب مكالمات Discord الصوتية **لحظياً**: بمجرد دخول أحدهم القناة الصوتية،
ينضم البوت ويبدأ التفريغ النصي فوراً، يحلّل كل جملة عبر نموذج لغوي محلي،
ويعرض كل ذلك على لوحة (Dashboard) حيّة — ثم يُصدر تقريراً نهائياً عند انتهاء المكالمة.

```
Discord Voice ──► Whisper محلي (STT) ──► LLM محلي (تحليل) ──┐
                                                         ▼
                              Dashboard حيّ  ◄──  WebSocket /ws/voice
```

كل شيء يعمل في **عملية واحدة** (`python app.py`): السيرفر + اللوحة + البوت.

---

## المكونات

| الملف | الدور |
|---|---|
| `app.py` | نقطة الدخول — FastAPI + خدمة صفحات الواجهة + يشغّل البوت داخل نفس العملية |
| `discord_bot.py` | بوت Discord: التقاط الصوت، التقطيع، التفريغ، التحليل، التقرير |
| `whisper_service.py` | تحويل الصوت إلى نص عبر Whisper المحلي (faster-whisper، GPU) — حيّ + تقرير بأزمنة |
| `pipeline/` | حزمة معالجة معيارية **إضافية**: قاموس مصري + منظّف تفريغ حتمي + مفسّر لهجة (مقصود ضمني) + محرّك مشاعر (١١ شعور + خط زمني) |
| `llm_service.py` | التحليل اللحظي + التقرير النهائي (LM Studio / Ollama) |
| `websocket_handler.py` | بثّ النتائج لكل لوحة مفتوحة عبر WebSocket |
| `config.py` | الإعدادات المركزية (من `.env`) |
| `../frontend/` | صفحات الواجهة (login + لوحات الأدوار) — يقدّمها `app.py` |

## المتطلبات

- **Python 3.11+**
- **Whisper محلي** — يُنزَّل النموذج تلقائياً أول تشغيل (`large-v3` ~3GB). لا مفتاح ولا إنترنت بعد التنزيل.
- **(اختياري) GPU من NVIDIA** لتفريغ لحظي سريع بـ `large-v3`. ثبّت مكتبات CUDA:
  `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12 nvidia-cuda-runtime-cu12`
  (بدون GPU يعمل على CPU تلقائياً — استخدم موديل أخفّ مثل `small` للسرعة عبر `WHISPER_MODEL`).
- **LM Studio** (أو Ollama) يعمل على `http://127.0.0.1:1234/v1` مع نموذج محمّل (للتحليل/التقرير)
- **بوت Discord** مع تفعيل **Message Content Intent** في
  [Discord Developer Portal](https://discord.com/developers/applications)
- على ويندوز: `libopus-0.dll` مرفق في `voice-model/` (يُحمّل تلقائياً)

```bash
pip install -r requirements.txt
```

## التشغيل

هذا الموديل جزء من نظام **Smart Call Monitor** — لتشغيل كل المكوّنات معاً راجع
[`README.md`](../README.md) في الجذر (أو شغّل `start-all.bat`).

لتشغيل الموديل وحده:

```bash
cd voice-model
python app.py
```

ثم افتح صفحة الدخول: **http://127.0.0.1:8080/login.html**

> **مهم:** `python app.py` يشغّل **السيرفر والبوت معاً** في عملية واحدة.
> لا تشغّل `python discord_bot.py` في نفس الوقت — ذلك يفتح نسخة ثانية من البوت
> بنفس التوكن، كما أن تشغيله وحده (بدون السيرفر) يجعل رسائل اللوحة تفشل
> (`POST ... refused`). للتشغيل المنفصل: شغّل `app.py` أولاً ثم `discord_bot.py`.

السجلات يجب أن تُظهر:
```
Config ✅ — Whisper=large-v3 (auto, ar) | LLM=...
[Whisper] ✅ الموديل جاهز: 'large-v3' @ cuda (int8_float16)
✅ Opus loaded from ...libopus.dll
✅ البوت متصل: Call Monitor Bot#....
```

## الاستخدام

1. شغّل `python app.py` وافتح اللوحة في المتصفح.
2. **ادخل أي قناة صوتية في سيرفر Discord** — البوت ينضم تلقائياً ويبدأ المراقبة
   (`AUTO_JOIN=true`). أو اكتب `!join` في قناة نصية وأنت داخل قناة صوتية.
3. تكلّم — يظهر التفريغ والتوجيهات على اللوحة لحظياً.
4. عند خروج آخر شخص من القناة (أو كتابة `!leave`) يُفصل البوت ويُصدر
   **تقرير ما بعد المكالمة** (ملخص / هل حُلّت المشكلة / تقييم الموظف / ملاحظات).

## الإعدادات (`.env`)

انسخ `.env.example` إلى `voice-model/.env` وعدّل ما يلزم:

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `DISCORD_TOKEN` | *(مطلوب)* | توكن البوت — يُفضّل وضعه هنا بدل الكود |
| `AUTO_JOIN` | `true` | انضمام تلقائي بمجرد دخول أول شخص قناة صوتية |
| `WHISPER_MODEL` | `large-v3` | نموذج التفريغ (الأقوى). بدائل أخفّ: `medium`, `small`, `base`, `tiny` |
| `WHISPER_DEVICE` | `auto` | الجهاز: `auto` (GPU لو متاح وإلا CPU) · `cuda` · `cpu` |
| `WHISPER_COMPUTE_TYPE` | *(تلقائي)* | فارغ=تلقائي (cuda→`int8_float16`، cpu→`int8`). للجودة القصوى على GPU مخصّص: `float16` |
| `WHISPER_LANGUAGE` | `ar` | لغة التفريغ (Whisper يستخدم رمز ISO عام؛ `ar` يشمل المصرية) |
| `WHISPER_HOTWORDS` | *(قائمة config)* | مصطلحات كول سنتر يُرجّحها النموذج لرفع الدقة (اتركه فارغاً للافتراضي) |
| `TEXT_CLEANER_ENABLED` | `true` | تنظيف تفريغ حتمي (تكرار/مسافات/ترقيم + قاموس مصري) مع الحفاظ على اللهجة — بلا LLM |
| `DIALECT_INTERPRETER_ENABLED` | `true` | حقن تلميحات المقصود الضمني للتعبيرات المصرية في برومبت التحليل والتقرير — بلا LLM |
| `EMOTION_ENGINE_ENABLED` | `true` | اكتشاف ١١ شعوراً من كلام العميل + خط زمني، يُحقن في التحليل والتقرير — بلا LLM |
| `CORRECTION_ENABLED` | `true` | تصحيح أخطاء التفريغ بنموذج لغوي محلي قبل التقرير النهائي |
| `LLM_MODEL` | `qwen2.5-7b-instruct` | اسم النموذج في LM Studio (للتحليل/التقرير) |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:1234/v1` | عنوان الـ LLM |
| `PORT` | `8080` | منفذ السيرفر واللوحة |

## الدقة والزمن الحقيقي

التفريغ يتم عبر **Whisper المحلي** (`faster-whisper`/CTranslate2) — محلي بالكامل بلا
أي API أو تكلفة. على GPU (NVIDIA) يعمل `large-v3` لحظياً (مقطع 12ث ≈ 0.7ث على RTX 3070).
النظام يعمل بمسارين لأعلى دقة:

- **الحيّ:** كل مقطع كلام يُفرَّغ فوراً (وضع سريع) لعرض نص لحظي على اللوحة (لمساعدة الموظف).
- **التقرير:** عند انتهاء المكالمة يُعاد تفريغ **كامل الصوت** بوضع دقيق (beam أكبر + تراجُع
  حراري + سياق) مع **أزمنة المقاطع**، ثم يُنسب كل جملة للمتحدّث **المعروف** من قنوات
  Discord المنفصلة (أدقّ من diarization)، ثم يمرّ على **تصحيح لغوي** اختياري
  (`CORRECTION_ENABLED`) قبل بناء التقرير.

**Hotwords** (قائمة مصطلحات الكول سنتر في `config.py`) ترفع دقة تعرّف النموذج على
أسماء الشركات والمصطلحات التقنية وألفاظ خدمة العملاء — وتُدمج تلقائياً مع `company_terms`
من القاموس المصري القابل للتحرير بدون كود.

**رفع دقّة Whisper للمصري** (`whisper_service.py` + مفاتيح `WHISPER_*` في `config.py`):
`initial_prompt` يُمهّد النموذج بلهجة ومصطلحات المكالمة المصرية؛ `beam_size` (٥ حيّ / ١٠ تقرير)
مع `best_of=8` و`patience=2` و`repetition_penalty=1.15` توسّع البحث وتقلّل الهلوسة؛ VAD أقصر
للصمت (٢٥٠مللي) يقسّم الكلام أدقّ؛ و`word_timestamps` يعطي ثقة كل كلمة. **تحليل ثقة** (من
`avg_logprob` و`compression_ratio` و`no_speech_prob` وأقل احتمال كلمة) يحدّد المقاطع الضعيفة،
و**إعادة تفريغ تكيّفية** تعيد تفريغ *هذه المقاطع وحدها* بإعدادات أدقّ وتستبدل النص لو تحسّنت
ثقته — أعلى دقّة بأقل تأثير على الأداء. كله خلف مفاتيح `WHISPER_*` بقيم افتراضية آمنة (أطفئ
الإعادة التكيّفية بـ `WHISPER_ADAPTIVE_RETRANSCRIBE=false`). لا يتغيّر أي API أو مخرجات.

**تنظيف التفريغ (منظّف حتمي — `pipeline/`)**: يمرّ نص Whisper (حيّ وتقرير) على منظّف
سريع بلا LLM يشيل تكرار الكلمات ويظبط المسافات والترقيم والإطالة، ويصحّح أخطاء تفريغ
شائعة من **قاموس مصري قابل للتحرير** (`pipeline/dictionary/egyptian_dictionary.json`)
— **مع الحفاظ على اللهجة المصرية زي ما هي** (بلا تحويل لفصحى وبلا تغيير المعنى). عدّل
القاموس بدون كود (أو وجّه `SCM_DICTIONARY_PATH` لملف خارجي)، وأطفئه بـ
`TEXT_CLEANER_ENABLED=false` للرجوع للنص الخام. الأزمنة لا تتأثر، فنسب المتحدّثين يبقى دقيقاً.

**مفسّر اللهجة المصرية (`pipeline/dialect/`، الخطوة 4)**: يكتشف التعبيرات المصرية ذات
المقصود الضمني (`هحاول` = التزام غير مؤكد · `ربنا يسهل` = تأكيد ضعيف · `هشوف` = رد
مؤجّل · `تمام` = موافقة قد تكون تهكّمية) ويحقن معناها كتلميحات مختصرة في برومبت **التحليل
اللحظي والتقرير** — فيفهم الموديل المقصود بدل ما يخمّنه (مثلاً ميعتبرش وعداً ضعيفاً حلاً
مؤكداً). الاكتشاف حتمي وسريع (بلا LLM إضافي)، والتفسير النهائي يبقى **سياقياً** لأن
التلميحات تُقدَّم مع سياق المكالمة كامل. المعجم قابل للتحرير:
`pipeline/dialect/dialect_lexicon.json`؛ أطفئه بـ `DIALECT_INTERPRETER_ENABLED=false`.

**محرّك المشاعر المصري (`pipeline/emotion/`، الخطوة 8)**: يتخطّى «إيجابي/سلبي» ويكتشف
**١١ شعوراً** من كلام العميل (غضب · إحباط · حيرة · خوف · توتر · رضا · حماس · تردد ·
تهكّم · استعجال · ثقة) بعبارات مصرية دالّة، مع **حارس نفي** (`مش قلقان` ≠ خوف)
و**تهكّم سياقي** (مديح ساخر + غضب/إحباط). في التقرير يبني **خطاً زمنياً** لمشاعر العميل
(البداية · الأبرز · النهاية · الاتجاه: تصاعد/تحسّن) يُحقن في البرومبت فيتحسّن
`customer_sentiment` واللحظات الحرجة؛ وفي التحليل اللحظي يعرض قراءة شعورية للدور عند أي
انفعال سلبي. حتمي وسريع (بلا LLM). المعجم قابل للتحرير:
`pipeline/emotion/emotion_lexicon.json`؛ أطفئه بـ `EMOTION_ENGINE_ENABLED=false`.

> بلا تكلفة تشغيل — كله محلي. الحمل على الـ GPU/CPU فقط.

التفريغ والتحليل يعملان في **مسارين منفصلين**: يظهر النص فوراً، أما تحليل الـ LLM
فيُبثّ عند جهوزيته (وإن تأخّر تُسقَط التحليلات القديمة تلقائياً حتى تبقى لحظية).

## ⚠️ ملاحظة أمنية

توكن Discord مكتوب حالياً داخل `voice-model/discord_bot.py` كقيمة احتياطية، وهو **مكشوف**.
يُنصح بشدّة بـ:
1. إعادة توليده (Regenerate) من Discord Developer Portal.
2. وضع الجديد في `voice-model/.env` كـ `DISCORD_TOKEN=...` (يُقرأ تلقائياً ويتقدّم على القيمة المضمّنة).

## استكشاف الأخطاء

| العَرَض | الحل |
|---|---|
| لا يظهر شيء على اللوحة | تأكد أن السيرفر يعمل وأن شارة "متصل 🟢" ظاهرة أعلى اللوحة |
| `POST ... refused` في سجل البوت | تشغّل البوت وحده بدون السيرفر — شغّل `python app.py` بدلاً منه |
| البوت لا ينضم للقناة | فعّل **Message Content Intent**، وتأكد أن للبوت صلاحية الدخول/الاستماع |
| `Opus not loaded` | تأكد من وجود `voice-model/libopus-0.dll` (ويندوز) |
| `OpusError: corrupted stream` أو كلام مُهلوَس | كان بسبب تشفير Discord الطرفي (DAVE/E2EE)؛ يفكّه البوت الآن تلقائياً عبر جلسة DAVE (يتطلّب `davey`) |
| `WebSocket closed with 4017` | لا تُعطّل DAVE بإعلان الإصدار 0 — Discord يمنع ذلك. البوت يدعم DAVE ويفكّه |
| لا يظهر تفريغ | تأكد أن النموذج حُمِّل (`✅ الموديل جاهز` في السجل)، وأن الصوت ليس صامتاً |
| `cublas64_12.dll is not found` | مكتبات CUDA ناقصة — `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12 nvidia-cuda-runtime-cu12` (أو يتراجع لـ CPU تلقائياً) |
| التفريغ بطيء جداً | يعمل على CPU — فعّل الـ GPU، أو خفّف الموديل: `WHISPER_MODEL=small` |
| التحليل/التقرير فارغ | تأكد أن LM Studio يعمل والنموذج محمّل على `:1234` |
